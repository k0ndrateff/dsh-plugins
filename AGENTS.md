# AGENTS.md

Правила работы в этом репозитории. Читать целиком перед первой правкой; раздел
«Код-стайл» — обязательный, остальное — карта местности.

## 1. Что это

Плагины для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness):
интеграции с внешними системами, которые дают агенту тулы, а человеку — карточки
и панели внутри харнесса вместо переключения в браузер.

Текущее состояние — Atlassian (Jira + Confluence). Куда идём — [docs/roadmap.md](docs/roadmap.md):
библиотека OAuth для MCP, затем Sentry, GitLab, Figma, плагин проверок и дайджест.
**M0 сделана**: `dsh-mcp-oauth` вынесена, Atlassian-плагин работает на ней.
Активная веха — **M1**: мультиаккаунт в credential-записи и no-auth режим.

## 2. Структура

Монорепа, пакеты в `packages/`. Плагин (то, что ставит пользователь) — npm-пакет
с `dsh.bundle.patch`; библиотека — npm-пакет без него.

```
packages/
├── mcp-oauth/     dsh-mcp-oauth         библиотека: OAuth для MCP-серверов
└── atlassian/     dsh-atlassian-plugin  бандл: Jira и Confluence
```

Внутри каждого пакета:

```
src/host/     половина, которая живёт в процессе харнесса
src/client/   половина, которая живёт в браузерной странице
src/shared/   типы, о которых обе половины договариваются
test/         проверки, запускаются bun
lib/          собранное (в git не хранится)
```

Плановые пакеты (`sentry`, `gitlab`, `figma`, `devkit`, `integration-ui`,
`plugin-build`, `workflow`) появятся по мере вех — имена зарезервированы в
roadmap.

## 3. Команды

Пакетный менеджер — **bun** (workspaces). `pnpm` в проекте не используется: он
принадлежит профилю харнесса, который просто линкует наш пакет.

```sh
bun install                     # из корня, ставит все workspace-зависимости

bun run build                   # из пакета: сборка его lib/
bun run typecheck               # tsc по обеим половинам
bun run test                    # проверки пакета
bun run watch                   # пересборка на изменениях
```

Перед тем как сказать «готово», прогнать в затронутых пакетах:
`typecheck` → `build` → `test`. Плюс проверку чистоты клиентского бандла (см. §7).

## 4. Устройство харнесса в двух абзацах

**Bundle** — npm-пакет с `dsh.bundle.patch`, то есть слой конфигурации, который
вставляет строку плагина в дерево Cordis. **Profile** — директория
`~/.dsh/profiles/<name>`, которая перечисляет бандлы; установка —
`dsh plugin --profile desktop add <путь>`, что просто делегирует в pnpm в
директории профиля. Пакет без `dsh.bundle` ставится как обычная зависимость —
это формат библиотеки.

**Половинки.** Хост-половина — обычный ESM-бандл, который грузит Cordis. Клиентская
— classic script, регистрирующий фабрику в `window.__ModuleLoader__.load({id,
factory})`; её `require` умеет **только** то, что перечислено в `build.mjs`
(`PLATFORM_MODULES`), всё остальное обязано быть инлайном или типом. Поэтому
между пакетами DSH не бывает runtime-импортов: только `import type` плюс сервисы
из `ctx`.

## 5. Код-стайл

Эталон — `packages/atlassian/src/client/host-api.ts`. Разберём, почему именно он:

- **Один класс — одна ответственность.** `HostApi` — это канал в хост-половину.
  Не «утилиты для fetch», не «api + кэш + ретраи», а ровно канал.
- **Узкая публичная поверхность.** Наружу — только осмысленные операции
  (`getPanel`, `assignIssue`), каждая с docstring. Вся механика (`request`,
  `failureOf`) — `private`.
- **Публичные методы читаются как оглавление.** По списку методов понятно, что
  пакет умеет, без чтения тела.
- **Docstring объясняет контракт, а не код.** «Move one issue through a workflow
  transition; answers with the fresh issue» — сказано, *что вернётся*; из тела
  это неочевидно.
- **Ни одного комментария, пересказывающего строку.** Комментариев в файле нет
  вообще, и он от этого не страдает.
- **Ошибка переводится на границе.** Хост отвечает `{error}` — `failureOf`
  превращает это в человеческое сообщение, и вызывающий код не разбирает HTTP.
- **Всё типизировано на входе и выходе**, включая generic у приватного хелпера.

### 5.1 Комментарии

Только два законных вида.

**Docstring** — на публичной поверхности: классах, публичных методах, экспортируемых
функциях, типах с неочевидным контрактом. Внутри docstring нужно: что это, зачем
существует, какие у него границы. `@param`/`@returns` — когда из подписи неясно
или есть неочевидный случай (пустой результат, исключение, побочный эффект).

```ts
/**
 * Resolve a possibly relative Atlassian path against the site's own root.
 *
 * A Confluence search answers with "/spaces/KEY/pages/123", which is relative
 * to the wiki, while a `webui` link already starting with `/wiki` is relative
 * to the site itself.
 */
```

**Комментарий по месту** — только если он объясняет **почему**, а не **что**.
Признак хорошего: удалив код, комментарий перестал бы быть понятным.

```ts
// A registration is bound to the exact redirect URIs it was issued for, and the
// loopback port is not guaranteed to be free, so reuse it only when both match.
```

Запрещено:

- пересказ кода (`// increment the counter`, `// return the result`);
- комментарий-заголовок перед очевидным блоком (`// Helpers`, `// Types`);
- устаревшие комментарии: правишь код — правишь или удаляешь комментарий рядом;
- история изменений в комментариях («раньше было так», «добавлено для X»);
- `TODO` без ответственного и причины. Если задача реальна — она идёт в
  `docs/roadmap.md`, а не в комментарий.

### 5.2 Слои и файлы

- **Одна ответственность на файл.** Имя файла отвечает на вопрос «что здесь
  лежит»: `discovery.ts`, `loopback.ts`, `grant.ts`. Если в файле оказались две
  темы — это два файла.
- **Разделять по уровням абстракции.** Транспорт (HTTP, сокеты) не знает про
  домен; домен не знает про UI; UI не ходит в сеть напрямую.
- **Домен не течёт в общий слой.** Библиотека не знает слов «Atlassian»,
  «Jira», «issue». Всё, что специфично для провайдера, приходит в неё
  параметром (профиль провайдера, набор скоупов, имя credential-записи).
- **Маленькие функции.** Если функция не помещается на экран — из неё
  выделяется шаг с именем. Приватный хелпер лучше длинного тела.
- **Чистые функции где можно.** Разбор, форматирование, выбор — без побочных
  эффектов; тогда их видно в тестах без моков.
- **Порядок в файле:** docstring модуля → импорты → константы → типы → класс →
  экспорт. Внутри класса: публичные члены, потом приватные, читаются сверху вниз
  в порядке вызова.

### 5.3 DRY и переиспользование

- **Сначала поиск, потом код.** Почти всё, что кажется новым, уже есть: в этом
  пакете или в `packages/mcp-oauth`.
- **Правило границы:** если это понадобится второму плагину — место в
  библиотеке, а не в плагине. Провайдер-специфичное — в плагине.
- **Одинаковое поведение — один код.** Пример: `toTokenFields` существует в
  одном экземпляре, потому что его требуют и code-, и refresh-обмен.
- **Копипаста build-обвязки** (`build.mjs`, `styles-runtime`) — известный долг;
  выносится в `dsh-plugin-build` на M8. Пока новый пакет копирует её осознанно,
  а не «потому что так вышло».
- **Переиспользуемая функция — та, у которой понятен вход и выход.** Если для
  повторного использования нужно знать внутренности — это не функция, а
  скрытая связность.

### 5.4 ООП

Логика — это объекты с состоянием и поведением, а не свалка функций и констант.

- **Класс владеет своим состоянием.** `LoopbackListener` владеет сокетом и
  промисом кода; `GrantStore` — записи и её обновлением. Никаких модульных
  `let` и «функций, которые принимают всё, что им нужно, включая ctx».
- **Инстанс вместо статики, когда есть состояние или ключ.** Статические методы
  уместны для чистых преобразований (`Grant.from(payload)`, `formatDuration`), и
  неуместны там, где объект естественно параметризуется (`GrantStore` знает
  свою credential-запись и не должен спрашивать её у каждого вызова).
- **Инкапсуляция, а не договорённость.** Поле, которое нельзя менять снаружи, —
  `private`/`readonly`; инвариант держится внутри.
- **Один класс — один уровень.** `McpOAuthBridge` соединяется и публикует тулы;
  разбор ответа — дело вызывающего, а не моста.
- **Не плодить иерархии.** Наследование — только когда есть подстановка
  (наследник обязан работать везде, где работает родитель); интерфейс лучше
  абстрактного класса, если нечего переиспользовать.

### 5.5 Формат

- Функции делаем стрелочными и объявляем через `const` (кроме `static` в классах).
- Отступы — табы, кавычки — двойные, точки с запятой — обязательны: `biome.json`.
  Форматирование делает `bunx biome check --write src test`, спорить с ним не надо.
- Имя файла — `kebab-case.ts`, класс — `PascalCase`, функция и переменная —
  `camelCase`, тип — `PascalCase`. Имя класса — существительное по роли
  (`PanelApi`, `GrantStore`), имя функции — глагол (`discover`, `parseGists`).
- Импорты: сначала типы, потом значения; из других пакетов DSH — `import type`,
  если это только типы.
- Экспорт поимённый; `export default` не используем.
- Булевы имена читаются утверждением (`isSignedIn`, `hasScreen`), а не `flag`.

## 6. Ловушки

Каждая из них уже стоила времени — не наступать снова.

- **Никаких runtime-импортов между пакетами DSH.** Приватные поля JS проверяются
  по классу: своя копия `@deepseek-ai/dsh-session` падает на
  `Receiver must be an instance of class Session`. Между пакетами — только
  `import type` и сервисы из `ctx`.
- **Клиентский бандл пускает только платформенные модули.** Всё остальное —
  инлайн. Проверка после сборки: `grep -o 'require("[^"]*")' lib/client.js | sort -u`
  должен давать только `react`, `react/jsx-runtime` и UI-кит.
- **vanilla-extract не принимает селекторы-потомки** (`& > :first-child`,
  `& h1`) — только `&` с модификаторами и `globalStyle` для остального.
- **`inject` — жёсткая зависимость.** Плагин, который ждёт сервис, отсутствующий
  в сборке, не активируется целиком. Необязательное берётся через
  `ctx.get(...)` в момент использования или через scoped `ctx.inject([...])`.
- **Имя тула на клиенте и на хосте должно совпадать.** `publicToolName` с
  дайджестом для длинных имён — один код на обе половины.
- **OAuth для MCP в харнессе не существует.** Стоковый `dsh-mcp-client` умеет
  только статический заголовок `Authorization`; всё остальное — наша библиотека.
- **У библиотеки два входа, и это не случайность.** `dsh-mcp-oauth` тянет
  node-модули и в браузерный бандл не годится; общая для обеих половин мелочь
  (правило именования тулов) живёт в `dsh-mcp-oauth/tool-name` и оттуда
  импортируется без node-типов.
- **Правка в библиотеке видна плагину сразу**: оба бандла собираются из её
  исходников через `alias` в `build.mjs`, а типы идут через `paths` в tsconfig.
  Собирать библиотеку перед плагином не нужно — её `lib/` существует только для
  публикации.

## 7. Проверка результата

1. `bun run typecheck` в затронутых пакетах — ноль ошибок.
2. `bun run build` — сборка без предупреждений, CSS инлайнится.
3. `bun run test` — все проверки зелёные. Живые проверки (OAuth против реальных
   эндпоинтов) требуют сети; они не должны падать из-за отсутствия логина.
4. Клиентский бандл — только платформенные `require` (§6).
5. Хост-бандл не тянет лишние пакеты: `grep -c "dsh-session\|dsh-llm" lib/index.js`
   должно быть нулём, если они не нужны.
6. В приложение — через профиль: `dsh plugin --profile desktop add <путь>`, затем
   **перезапуск харнесса** (хост-половина читается на старте) и обновление
   страницы (клиентская).
