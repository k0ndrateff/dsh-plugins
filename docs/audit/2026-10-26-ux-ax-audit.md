# UX/AX-аудит плагинов — 26.10.2026

Аудит интерфейсов для человека (UX) и для агента (AX) по всем бандлам монорепы.
На момент аудита исходники не менялись; исправления и решения — в разделе
«Статус исправлений» в конце. Четыре параллельных прохода по пакетам дали подробные
таблицы с построками и доказательствами (рабочие файлы — в `.tmp/ux-ax/`, в git
не коммитились); здесь — сведённый, дедуплицированный и приоритизированный
результат.

**HEAD:** `cba9ccb`. **Охват:** `atlassian`, `sentry`, `gitlab`, `figma`, `browser`,
`digest`, `correlation`, `devkit`, `integrations`, общие `integration-ui`,
`integration-host`, `mcp-oauth`, установка (`workflow`, `docs/market.json`, README).

**Как проверялось.** Четыре параллельных прохода по пакетам плюс отдельный проход
по общим слоям и установке: чтение `src`, манифестов, patch-файлов, README,
`docs/browser.md`, прошлого аудита `docs/audit/2026-10-23-audit.md` (закрытые
пункты не повторяются) и `node_modules` UI-кита (чтобы видеть доступные, но
неиспользованные примитивы). Запуском ничего не проверялось: сборки, тесты,
`bun install`, живые роуты и Web GUI не трогались; опубликованный GUI содержит
`dsh-workflow-plugin@0.1.5` и не отражает HEAD. Поэтому все находки — свойства
кода, а не воспроизведение в браузере.

**Приоритеты.** `P1` — типовой сценарий не выполняется или состояние вводит в
заблуждение; `P2` — заметное трение, обход существует; `P3` — полировка.
Итог: **6 × P1, 52 × P2, 13 × P3** (P3-строки группируют несколько мелких находок).

## Главное в одном абзаце

Плагины уже хорошо спроектированы там, где решение принималось один раз на общем
слое: карточки, панели, реестры источников, confirm-гейт GitLab. Системные
проблемы — в другом: **статусы и ошибки смешаны** (нормальные состояния
рисуются красным, ошибка провайдера выдаётся за пустой результат), **лимиты не
живут в контрактах** (агент не может сказать «N из M»), **ошибки не переводятся
на границе** (MCP `isError`, OAuth, Figma), **запись не отчитывается** (панель
молчит, агентские write-тулы без инструкции), а **первый запуск** не имеет ни
единой точки входа: установка одного плагина вообще не даёт страницы настроек.

## Пять системных правил, которые стоит зафиксировать

1. **Статус ≠ ошибка.** Нормальные состояния (нет браузера, закрыт, не подключён,
   идёт вход) и настоящие сбои должны идти разными полями и разными цветами.
   Сейчас это одна строка `error` в панели браузера, один `status.error` в
   карточках и один красный `<p>` в общей панели.
2. **Лимит живёт в контракте.** `total`, `truncated`, `next` (и число
   отброшенных) нужны в схеме результата, а не только в голове автора: иначе ни
   модель, ни карточка не могут сказать «N из M». Сейчас это уже сделано в
   GitLab-диффе и `checks`, но не в `present`, `digest`, `correlate`, списках MR.
3. **Ошибка переводится на границе.** Три места, где это не так: `McpBridge`
   (`isError` как данные), OAuth-callback/discovery (сырые коды), Figma optional
   reads (сбой → «нет данных»). Один хелпер на класс проблемы дешевле, чем
   правка в каждом туле.
4. **Запись должна отчитываться.** После действия человеку нужен видимый
   in-flight и успех, агенту — инструкция сообщить, что изменилось. GitLab
   ConfirmRow — эталон; панели Sentry/Atlassian и MCP write-тулы — нет.
5. **Один вход.** Сейчас onboarding зависит от того, какой бандл поставили:
   workflow даёт страницу Integrations, одиночный плагин — нет. Пока это не
   исправлено, README не должен предлагать одиночную установку как равную.

- **Терсные строки тулов** (`integration-ui/src/tool/row.tsx`): транскрипт не
